# v0.2 Samsung playback proof: operator runbook

## 1. Deploy the checked build

1. On the ARM64 VPS, copy `.env.example` to `.env` and set `PUBLIC_DOMAIN`, `PUBLIC_BASE_URL`, `ADMIN_API_KEY`, and `TOKEN_HMAC_SECRET`.
2. Start the core stack:

   ```bash
   docker compose -f infra/compose.yml up --build -d
   ```

3. Confirm the public health endpoint returns `status: ok` and that the private admin plane is reachable only over VPN or an SSH tunnel.

   ```bash
   ssh -N -L 3000:127.0.0.1:3000 user@vps
   ```

## 2. Prove Samsung AVPlay first

1. Create an MSX device through `POST /admin/devices` with `x-admin-key`.
2. Put the returned `startUrl` into Media Station X.
3. Open **Samsung 2017 AVPlay diagnostics**.
4. Test MP4 + external SRT, HLS with 10/15/20 second buffers, pause/resume, and seek forward/back.
5. While a clip is playing, use the content-button Tizen inspector to check AVPlay information and tracks.
6. Record each pass/fail result with `POST /admin/devices/:id/diagnostics`.

Do not proceed if HTTPS, MP4, HLS, seeking, or external SRT fail.

## 3. Add one real authorized CloudStream archive

1. Copy exactly one operator-authorized `.cs3` archive into the `cloudstream-plugins` Docker volume.
2. Start the compatibility profile with an empty allowlist first:

   ```bash
   docker compose -f infra/compose.yml --profile cloudstream-compat up --build -d
   ```

3. Through the private admin API, inspect the archive:

   ```http
   POST /admin/cloudstream/plugins/inspect
   { "fileName": "your-plugin.cs3" }
   ```

4. Review the returned SHA-256 and plugin class. Add that exact SHA to `PLUGIN_ALLOWLIST_SHA256` in `.env`, then recreate the compatibility service.
5. Execute it through `POST /admin/cloudstream/plugins/execute`. A timeout or failure is recorded; repeated failures are quarantined in the plugin trust record.

The sidecar confirms that the plugin loads safely. Do not authorize a replacement archive merely because it has the same filename.

## 4. The final engineering gate

The current sidecar intentionally returns `loaded_without_provider_adapter` after a real plugin loads. Supply the resulting provider class/API behavior for that single authorized archive, then implement and test its exact `search -> load -> loadLinks -> ExtractorLink[]` adapter. Only after it emits normalized links should it be added to the unified resolver.

## 5. Acceptance test

For the same real title: resolve the source, verify the playback plan, press Play on the physical Samsung, then check AVPlay READY/PLAYING, seek, pause, resume, external subtitle load, and reopening at the stored position.
